# LexiStory 产品与工程评估

评估日期：2026-10-11。基于本地源码、桌面和手机尺寸的浏览器操作、自动化测试与构建；没有真实用户留存数据，不把主观体验改善当成已验证的留存增长。

用户确认：目前没有部署网址，手机端先做 Android。iOS 保留工程基础，后续再推进。

## 判断

这个项目已经具备可试用的学习闭环：选择学习内容、生成文章、逐句阅读、单词与语法入册、测验、间隔复习。最有价值的方向是让用户在一篇可读的文章里遇见自己的生词，并在后续文章中再遇见它们。现阶段适合邀请少量用户持续试用，尚不能作为有账号同步、稳定配额与完整运维保障的公开商业服务。

优先服务考研英语学习者比较明确。小学、初中可以保留，但教材范围、生成难度和引导文案需要分别验证。词表数量、等级标签、摸底结果并不等同于经过标准化验证的能力测评。

## 本轮已落地

| 环节 | 原问题 | 改动与用户收益 |
| --- | --- | --- |
| 首次进入 | 先答 20 题，再等待 AI 生成；价值出现得太晚 | 增加一分钟体验文章，不需要测试或等待，直接试词义、解析、朗读和测验 |
| 界面 | 层级与入口容易混杂 | 延续暖白、深绿的阅读风格；桌面侧栏、手机底栏；增加偏好与安装页；修复解析面板遮挡正文和标签过度渐隐 |
| 句子交互 | 点句子会自动朗读 | 点句子只选中并展示解析，点播放才开始；高亮词独立打开词卡 |
| 语音 | 没有清晰暂停、继续、取消，旧请求可能串播 | 独立播放器状态、暂停/继续/重播/语速、加载可取消；切句与关闭停止；隐藏页面暂停；取消旧请求；缓存限 20 条并释放 |
| 语音后端 | 无取消传播，断连要等超时 | 传递请求取消，断连立即失败；补充服务事件 ID、英文语言参数；无云语音时使用设备语音 |
| 阅读反馈 | 打开 3 秒即算已读 | 显式“我读完了”，或完成测验后记录；同一篇不重复累计或重复曝光；实际出现的词才入册；当天重复测验不反复提高掌握度 |
| 再次进入 | 找不到上次读到哪里 | 首页继续阅读卡片、句子书签、历史文章已读/待继续状态 |
| 学习统计 | UTC 日期造成凌晨错日；总文章数最多 100 | 使用本机日历日期；复习也延续学习天数；过期连续天数归零；保留阅读 ID 去重 |
| 生成等待 | 正文已就绪还要等整篇解析 | 正文生成后立即保存并打开；读者可先读，逐句解析随后补齐；解析可暂停，重试只请求缺少的句子；首页和重新生成均可取消 |
| 解析缺失 | AI 漏掉解析后句子可能无法点击 | 根据正文分句补齐交互；缺少解析时仍可朗读；新增解析保持当前选句与播放器状态，已完成阅读的语法会补入学习记录 |
| 测验中断 | 刷新、离开就丢掉答案 | 每次确认答案保存到本机；回来可继续或查看上次结果；完成后可逐题回看答案与解释；按钮与反馈改为中文 |
| 复习负担 | 每组 10 题，目标随着到期词减少而缩水 | 每组 5 题；开始判分前固定当日复习目标；只有能生成真实语境填空的单词才计入可练数量 |
| 保存失败 | 多个记录写到一半出错，可能留下半份成绩 | 阅读完成、测验交卷和语境填空的本地写入失败时回滚；成功保存后才显示完成，答案保留供重试 |
| AI 格式异常 | 无效选项或嵌套字段可能让界面报错 | 校验题目答案范围、过滤无效题目，清理逐句解析的字段；不匹配原文的解析不会覆盖正文 |
| 保存与误操作 | 无效备份可能先清空数据，旧快照不一定可恢复 | 导入前验证与预览、用户确认、新鲜恢复快照、失败回滚、导入撤回；历史文章/单词删除有本页撤销 |
| 手机体验 | 只有响应式网页 | PWA 安装信息、图标、安全区域、离线文章页；Capacitor Android/iOS 工程，前端本地打包，Android 返回键、原生备份分享 |
| API 边界 | 请求内容缺少统一边界 | JSON 类型、流式大小上限、字段与数量校验；原生来源 CORS；基础单进程限流 |
| 工程管理 | 大量功能未提交、缺少回归检查 | 先保存原有功能快照，再提交本轮改进；新增功能测试、CI、手机构建脚本及文档；排除密钥、日志、归档和生成资源 |

打开文章不再自动预生成下一篇，减少未明确使用时的付费请求。已有预生成缓存仍可打开。首页词义补全仍会调用配置的 AI 服务。

## 尚未解决的重点，按下一步优先级排列

1. **账号和跨设备同步。** 当前浏览器、PWA 和原生 App 使用各自本地存储；同一个人换设备不会自动带走进度。下一步需要认证、数据库、冲突合并和可撤销的数据删除。现有备份转移是过渡方案。
2. **上线后的费用与可靠性。** 单进程、按请求头 IP 的限流不能替代登录后的用户配额或分布式限流，也不能被当成鉴权。公开部署前补充账户配额、可信代理 IP 策略、请求日志脱敏、错误监控、服务预算和持久备份。
3. **内容质量。** AI 可能给出错误释义、语法和题目。需要按难度准备人工校验样本，对生成结果做质量抽检，加入“这句讲解有问题”的反馈入口。当前摸底是自评辅助，不应宣称准确测出 CEFR 或考试分数。教材词表来源与对外使用范围也应确认。
4. **学习有效性。** 本轮解决了打开即计分，并限制同篇测验每天只调整一次 SRS；重做仍保留成绩。接下来需要用真实学习者的遗忘情况验证复习间隔、题目难度和掌握标准。
5. **生成任务恢复。** 已实现正文先展示、解析随后补全；已经保存的正文可从历史找回。正文生成完成之前关闭页面，当前仍会取消请求。后续需要服务端持久任务和任务 ID，才能在应用完全关闭后继续生成并找回结果。
6. **手机真机与发布。** 需要部署 HTTPS 后端、Android SDK/JDK、macOS/Xcode、签名账号，以及 iPhone/Android 真机测试。设备语音受系统英语音色和浏览器实现影响，尤其暂停/继续需要真机回归。尚未产出签名 APK/IPA，也未上架。
7. **无障碍细节。** 已补句子键盘操作和播放器标签；手机抽屉的焦点管理、读屏导航、放大字体后的全部页面仍需专门测试。首次入口和复习入口可继续减少术语。

## 怎样知道用户愿意继续使用

先找 5–10 位目标用户，观察他们实际完成首篇的过程，不替他们操作。每次只改最明显的阻塞点。

- 首次价值：打开后是否在 1 分钟内看到并理解一篇文章的用法。
- 激活：从进入 → 点开体验/生成 → 完成阅读 → 完成一次复习，各步流失在哪里。
- 回访：第二天和第七天有没有回来，是否能接着读，并完成一项小任务。
- 质量：语音失败比例、生成耗时、取消比例、解析缺失比例和备份失败比例。
- 学习反馈：一周后能否在新文章里认出练过的词，是否愿意继续用。

这些是待采集的指标，本轮没有加入第三方追踪，也没有编造留存或转化数字。

## 验证范围

- 自动化覆盖：音频播放/暂停/恢复、取消与竞态、旧回调、设备降级、缓存释放；阅读幂等、书签、当地午夜、连续天数、超过 100 篇的统计；备份坏文件/新版本/配额失败/恢复；API 请求边界；缺少句子解析。
- 2026-10-12 追加覆盖：正文先保存、不等待解析；取消后不保存；解析重试、迟到响应与已删除文章；后到语法不重复累计；AI 格式异常；测验草稿恢复/变更失效；阅读和交卷写入失败回滚；复习目标固定与不可出题的句子过滤。
- 浏览器人工回归：立即体验、点句子不播放、云端播放/暂停/继续/切句停止、手机 390 px 无横向溢出、完成阅读后刷新保留。
- 工程检查：ESLint、TypeScript、网站生产构建、移动端静态前端构建、Capacitor 工程生成与资源同步。
- 尚未完成：真实 iPhone/Android 音频与备份操作、原生二进制编译、签名、商店审核、真实用户留存实验。

实现依据：[Next.js PWA](https://nextjs.org/docs/app/guides/progressive-web-apps)、[Capacitor 配置](https://capacitorjs.com/docs/config)、[Qwen-TTS 会话协议](https://www.alibabacloud.com/help/en/model-studio/qwen-tts-realtime-client-events)、[浏览器语音暂停](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/pause)。开发时同时阅读了本项目安装的 Next.js 16 文档。

## 产品取舍（2026-10-12）

近期围绕“读一篇 → 懂几句 → 记几个词 → 下次能接着学”打磨，比继续增加入口更有价值。主入口保持每日阅读，填空和翻译作为读完后的下一步；一组练习控制在 5 题，用户完成一小段也能安心离开。通过真实试用观察用户是否理解下一步、在哪里退出，再决定是否增加排行榜、打卡激励等功能。

本地写入回滚只覆盖当前标签页的一次同步操作，不能替代跨标签页锁、云端事务或停电恢复。测验草稿保留最近 50 篇，正式成绩仍在学习历史中；未确认的选择不保存。AI 格式校验也不代表教学内容正确，需要人工抽检。
